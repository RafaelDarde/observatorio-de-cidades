# Site Web — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Site estático em Next.js com busca, perfil de cada município, comparação de até 3, rankings e página Sobre, consumindo os JSONs do pipeline.

**Architecture:** App Router com `output: 'export'`. Os perfis são pré-gerados no build lendo `web/public/dados/` via `fs`. Comparar e Rankings carregam os JSONs no cliente com `fetch`. A lógica (formatação, busca, slug, parsing de URL, filtros) fica em funções puras em `lib/`, testadas com Vitest. Os componentes só renderizam.

**Tech Stack:** Next.js (App Router), TypeScript, Tailwind, Recharts, Vitest, Playwright e json-schema-to-typescript.

**Spec:** `docs/superpowers/specs/2026-11-08-observatorio-de-cidades-design.md`

**Pré-requisito:** o plano `2026-11-08-pipeline-de-dados.md` concluído, com `web/public/dados/` populado e `schema/dados.schema.json` existente.

## Global Constraints

- Tudo estático: nada de rotas de API, `fetch` no servidor nem dependência de servidor em produção.
- Os tipos dos dados vêm só de `lib/tipos.ts`, gerado por `npm run tipos` a partir de `../schema/dados.schema.json`. Nunca é editado à mão.
- Os rótulos, unidades e descrições de indicador vêm de `catalogo.json`. Nenhum nome de indicador fica escrito em componente, exceto os 4 ids dos cartões do perfil e o id dos destaques da home, fixados pelo spec.
- Rota do perfil: `/municipio/{cod}-{slug}`. Comparar: `/comparar?c=cod1,cod2,cod3`. Rankings: `/rankings/{indicador}`.
- Idioma e formatação: pt-BR. O valor ausente é exibido como `"Sem dado"`, seguido do `motivo_ausencia`.
- Comandos rodam em `web/`.

## Review Focus

1. **Nomes com apóstrofo e hífen** (`Sant'Ana do Livramento`, `Pingo-d'Água`, `Olho d'Água das Flores`): o slug precisa ser estável e sem caracteres especiais. Teste em `slug.test.ts`.
2. **Nomes repetidos em UFs diferentes** ("São José" e variações): a busca devolve todos, cada um com a UF. Teste em `buscar.test.ts`.
3. **`/comparar` com códigos duplicados, mais de 3, inválidos ou parâmetro vazio**: tira as duplicatas, mantém os 3 primeiros válidos e lista os inválidos. Teste em `comparar.test.ts`.
4. **Indicador com `ultimo: null` mas `serie` preenchida**: mostra o gráfico do histórico e "Sem dado no período mais recente", sem quebrar. Teste em `visualizacao.test.ts`.
5. **Valores negativos** (saldo de emprego): formatação com sinal e barras para baixo do zero. Teste em `formatar.test.ts`.

  - `slug(nome: string): string`, que normaliza, remove apóstrofos, troca não alfanuméricos por `-` e colapsa e apara os `-`

```ts

expect(formatarValor(9876, "pessoas")).toBe("9.876")
expect(formatarValor(52400, "pessoas")).toBe("52,4 mil")
expect(formatarValor(1332845, "pessoas")).toBe("1,3 mi")
expect(formatarValor(2.5e9, "R$")).toBe("R$ 2,5 bi")
```

- Test: `web/lib/comparar.test.ts`

**Interfaces:**
- Produces:
  - `parseCodigos(param: string | null, codigosValidos: Set<string>): { validos: string[]; invalidos: string[] }` separa por vírgula e apara espaços, ignora vazios, tira duplicatas mantendo a ordem, devolve até 3 válidos e lista os inválidos.
  - `montarUrl(codigos: string[]): string` devolve `/comparar?c=a,b,c`.

Mostra uma busca para adicionar município (desativada com 3 já escolhidos), um botão de remover por município, a alternância "Só relativos / Todos" (o padrão é só relativos, pelo `relativo` do catálogo), uma tabela-resumo (indicador × município, com o valor de `ultimo`) e um gráfico de linha sobreposto por indicador com `serie`. Os códigos inválidos aparecem num aviso discreto. Toda mudança de seleção atualiza a URL com `router.replace(montarUrl(...))`.
